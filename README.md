# nmap-xml-report

Офлайн CLI на Python 3.10+ для чтения **готовых XML-результатов Nmap**. Не запускает Nmap, NSE, команды из XML, XSL, DNS-запросы или дополнительные сетевые проверки. Установка зависимостей требует доступа к пакетам; работа установленной программы — офлайн.

## Установка и PowerShell (Windows 10/11)

Из папки проекта, с установленным Python:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install .
.\.venv\Scripts\python.exe -m nmap_xml_report parse .\examples\lab.xml
.\.venv\Scripts\python.exe -m nmap_xml_report summary .\examples\lab.xml
.\.venv\Scripts\python.exe -m nmap_xml_report export .\examples\lab.xml --format json --output .\report.json
.\.venv\Scripts\python.exe -m nmap_xml_report export .\examples\lab.xml --format csv --output .\report.csv
.\.venv\Scripts\python.exe -m nmap_xml_report export .\examples\lab.xml --format markdown --output .\report.md
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Активация venv не нужна, политика выполнения PowerShell не меняется. После установки также доступна команда `.\.venv\Scripts\nmap-xml-report.exe`.

## Kali Linux

Ожидается совместимость с Kali при Python 3.10+. **Фактическая проверка в Kali не проводилась**. GitHub Actions проверяет Ubuntu Linux и Windows, что не заменяет проверку Kali или каждой версии Windows 10/11. При отсутствии venv установите системный пакет `python3-venv` штатным пакетным менеджером Kali.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install .
.venv/bin/nmap-xml-report parse examples/lab.xml
.venv/bin/nmap-xml-report summary examples/lab.xml
.venv/bin/nmap-xml-report export examples/lab.xml --format json --output report.json
.venv/bin/nmap-xml-report export examples/lab.xml --format csv --output report.csv
.venv/bin/nmap-xml-report export examples/lab.xml --format markdown --output report.md
.venv/bin/python -m unittest discover -s tests -v
```

## Команды и данные

- `parse INPUT`: нормализованный JSON в stdout.
- `summary INPUT`: краткая текстовая сводка, состояния портов и предупреждения.
- `export INPUT --format {json,csv,markdown} --output PATH`: экспорт только в явно выбранный файл.
- `--max-bytes N` у каждой команды уменьшает лимит входного файла (по умолчанию и максимум 20 MiB).

Хосты содержат все адреса с атрибутами, hostname и статус. Порты содержат протокол, номер, исходное состояние, сервис, продукт, версию и дополнительную информацию. `open`, `closed`, `filtered`, `open|filtered` и другие состояния сохраняются отдельно; отсутствующее состояние становится `unknown`. Отсутствующие остальные поля — `null` в JSON, пустые ячейки в CSV, `unknown` в текстовом представлении. Номера портов остаются строками исходного XML.

Отдельно сохраняются начало/конец сканирования (Unix timestamps и текст, если есть), длительность и результат завершения. Программа не угадывает отсутствующее время. Предупреждения отмечают отсутствующие данные, незавершённый запуск и агрегированные `extraports`. Число в `extraports` не превращается в выдуманные номера портов.

JSON содержит `schema_version`, `scan`, `hosts`, `warnings`, `notice`. CSV использует строки `scan`, `host`, `port`, `extraports`; `host_index` связывает их, массивы адресов/имён и метаданные записаны как JSON внутри ячеек. Строки `host` сохраняют даже хосты без портов. Потенциальные формулы в CSV предваряются апострофом; используйте JSON для точного машинного обмена. Markdown содержит время, предупреждения и таблицы портов. HTML-экспорт не реализован; HTML-значения внутри Markdown экранируются.

Обнаруженная версия сервиса — наблюдение из отчёта, **не доказательство уязвимости**. Программа не определяет CVE и не проверяет сервисы повторно.

## Недоверенный XML и запись файлов

- Используется `defusedxml`; внешние DTD, внутренние DTD и объявления сущностей отвергаются. Разрешена только пустая декларация `<!DOCTYPE nmaprun>` без внешних ссылок и внутреннего набора. XML stylesheet и NSE-элементы игнорируются, XInclude не выполняется.
- Только UTF-8 (включая BOM) / ASCII; остальные кодировки, повреждённый XML и чужой корневой элемент приводят к понятной ошибке. Файлы не распаковываются, каталоги не принимаются.
- До разбора читается максимум лимит + 1 байт; во время разбора действуют лимиты глубины 64 и количества элементов 200 000. Это ограничение ресурсов, а не полная проверка по DTD Nmap.
- XML-значения не передаются в оболочку, subprocess, сеть или шаблоны XSL. Управляющие символы экранируются в терминальной сводке, HTML и синтаксис Markdown — в Markdown.
- Каталоги вывода автоматически не создаются. Новый файл открывается эксклюзивно. Существующий файл заменяется только после ввода `yes` в интерактивном терминале; в пакетном режиме возвращается ошибка. Нет флага принудительной перезаписи. Исходный XML нельзя выбрать как файл вывода; символьные ссылки при перезаписи отвергаются.
- Код завершения: `0` — успех (включая отчёт с предупреждениями), `2` — ошибка входа/вывода, аргументов или отмена замены. Запись не является транзакционной: сбой диска может оставить неполный файл. Используйте каталог, недоступный для конкурентного изменения другими пользователями.

## Проверки и ограничения версии 0.1

Тесты: несколько хостов, TCP/UDP, разные состояния, отсутствующие поля, время, все форматы, повреждённые/чужие документы, XXE, внешние DTD, расширение сущностей, ограничения размера/глубины/числа элементов, неподдерживаемая кодировка, инъекции Markdown/CSV/терминала, отсутствие сетевых/процессных вызовов, команды CLI и подтверждение перезаписи.

GitHub Actions запускает тесты с Python 3.10, 3.12 и 3.14 на Windows и Ubuntu. Реальные результаты конкретного запуска смотрите во вкладке Actions. Пример полностью синтетический: адреса документационных диапазонов, домены `.test`, вымышленные продукты и время.

Полный XML не сохраняется: NSE-вывод, OS fingerprints, traceroute, CPE и другие расширенные поля за пределами этой версии игнорируются. Отчёт с успешным завершением не доказывает полноту самого сканирования; программа предупреждает только о распознаваемых пробелах. Нет HTML, GUI, сканирования и автоматической оценки уязвимостей.

Standalone-файлы PyInstaller в этой версии **не собирались**. Если они потребуются, сборка и smoke-тест выполняются отдельно на Windows и отдельно на целевой Linux/Kali; Windows-сборка не считается Linux-сборкой.

Описание формата: [официальная документация Nmap XML](https://nmap.org/book/output-formats-xml-output.html). Защита XML: [документация defusedxml](https://pypi.org/project/defusedxml/).
